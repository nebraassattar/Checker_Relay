Think of the row as nested layers. Walk the first black checker left until it sits right behind the last red — that's n_pairs − 1 swaps. Slots 0 and 1 are now permanently correct, and what's left is the exact same shape of problem, one layer smaller.


            

              
the invariant

              
Before every call, the slice from offset holds n_pairs reds followed by n_pairs blacks — the same shape as the very first row, just narrower.

              
arr[offset : offset + 2*n_pairs] == [0]*n_pairs + [1]*n_pairs

            


            

              
one layer of work

              
The loop drags the first black checker — sitting at offset + n_pairs — left, one adjacent swap at a time, until it lands at offset + 1. That's the only place any swapping happens; see the loop and swap lines in the code tab.

              
for i in range(n_pairs - 1, 0, -1):
    left, right = offset + i, offset + i + 1
    arr[left], arr[right] = arr[right], arr[left]

            


            

              
base case

              
n_pairs == 0 means the slice is empty. Nothing left to fix, so solve() just returns — this is what finally empties the stack in the recursion tab.

            


            

              
why it's optimal

              
Each layer costs n_pairs − 1 swaps, so the total across all layers is

              
(n-1) + (n-2) + ... + 0 = n(n-1)/2

              
— exactly the number of red/black pairs that start out of order. No sequence of adjacent swaps can do it in fewer.
